# Session retro — environment improvements

**Session:** Stagecraft Studio v0, 26–27 October 2026. **Scope:** the agent environment, not the
product. The product retro is in [`retro.md`](retro.md).

## 1. Clean-checkout truth (fixed)

The first local `npm run check` passed only because `node_modules/stagecraft` was a symlink to the
private engine. CI failed on `thumbnails.ts` importing `stagecraft`. The fix was to exclude all
render-only pilot entries from the public typecheck. The guardrail is CI; the environment lesson is
to run the public gate in a clean clone before hand-off, not just in the working tree.

## 2. QA needed a checked-in render input (fixed)

`npm run qa` depended on a gitignored `tmp/qa` export. A clean clone could not run it. The fix is a
checked-in `qa/pilot.html`, regenerated by `render:pilot`, and a CI QA job with Playwright and
ffmpeg. The environment lesson is that every verification command must have a committed input or a
script that creates it.

## 3. TTS is the slow loop (open)

`npm run tts` regenerated all six scenes on every timing change. A text+voice+speed hash cache in
`tmp/voice/` would skip unchanged lines. This is the highest-leverage tool-economy fix for the next
episode.

## 4. Full renders are expensive (open)

The 90-second render is ~2 minutes; a still-first loop is cheaper. Add `render:pilot --stills-only`
and a `--scene <id>` path so a single scene can be re-rendered without touching the master. The
current `render-pilot.ts` always renders the full MP4, stills and HTML.

## 5. Media is duplicated (open)

The master and voice stems exist in both `public/demo/` and `handoff/` (~11 MB duplicate). Either
keep `public/demo/` as the single source and build `handoff/` on demand, or move the master to Git
LFS. The current 22 MB is under GitHub’s limit, so this is a hygiene issue, not a blocker.

## 6. Research lived outside the repo (fixed)

The initial research notes were in `../research`; the public repo now has `docs/research.md` and the
grill/spec/ADR chain. Keep the next investigation inside the project so the agent does not have to
cross workspace boundaries.

## 7. Live deploy needed a manual switch (fixed)

Pages had to be enabled once; `actions/configure-pages` with `enablement: true` failed with the
default token. Pages is now enabled, and the deploy workflow uses the repository setting. The
environment lesson is to enable Pages before the first `main` push or document the one-time step.

## Net

The reproducible path is now: clean clone → `npm ci` → `npm run check` → `npm run qa` → deploy. The
next investment is TTS caching and per-scene rendering, not more renderer features.
